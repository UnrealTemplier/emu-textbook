## 3. Ограничения, которые нужно соблюдать

Из `AGENTS.md` движка (прочитать полностью перед началом):

- Offline First: никаких внешних URL в ресурсах; внешние `<a href>` в тексте допустимы, поэтому ссылки на источник и лицензию в подписи разрешены.
- **Зависимости сборки:** только Python ≥ 3.11 и `markdown>=3.10,<3.11`. **Pillow и другие пакеты нельзя.** Размеры изображений читать из заголовков файлов средствами стандартной библиотеки. Клиентский код — Vanilla JS.
- Синтаксис Python 3.11 (`python3.11 -m py_compile engine/*.py engine/*/*.py`).
- Воспроизводимость: одинаковые входы дают побайтно одинаковый `dist/`. Копирование — побайтное, порядок обхода детерминированный.
- **Новая возможность — только за ключом `book.toml`, по умолчанию выключена.** Книги, не включившие ключ, не должны менять вывод: golden-тест демо и `verify_diff` на `go-textbook` должны пройти.
- Правила управления: этот документ — команда владельца на этап 1. Работать атомарными коммитами (`feat(engine):`, `feat(audit):`, `test:`, `docs:`, `chore(release): X.Y.Z`). **Push не делать.** Закончив этап 1, остановиться и доложить.

Ограничения хостинга книги (GitHub Pages, официальная документация «GitHub Pages limits»): опубликованный сайт — не больше 1 ГБ (жёсткий предел); исходный репозиторий — рекомендовано около 1 ГБ; трафик — мягкий предел 100 ГБ в месяц; публикация прерывается, если идёт дольше 10 минут. Отсюда нужен бюджет объёма изображений и контроль в аудите.

## 4. Этап 1 — функция «медиа» в движке (`html-textbook-engine`)

Ниже предложение, а не жёсткая спецификация. Имена ключей и детали можно уточнить, сохранив смысл; отступления записать в CHANGELOG и README.

### 4.1. Ключи `book.toml` (предложение: секция `[media]`)

```toml
[media]
enabled = false                 # по умолчанию выключено — вывод книг не меняется
dir_name = "media"              # подпапка рядом со страницами; сканер её не обходит как раздел
extensions = ["webp", "png", "jpg", "jpeg", "gif", "svg", "avif"]
credits_file = "credits.toml"   # файл атрибуции внутри каждой папки media/
figures = true                  # картинка отдельным абзацем → <figure> с <figcaption>
lightbox = true                 # увеличение по клику
credits_page = ""               # путь служебной страницы «Иллюстрации и лицензии»; "" — не создавать
# проверки аудита
require_alt = true
require_credit = true
allowed_licenses = ["PD", "CC0", "CC BY", "CC BY-SA", "own"]  # сравнение по префиксу/нормализованному имени
max_file_kb = 500
max_dimension_px = 2000
budget_mb = 700                 # суммарный объём медиа в dist/
```

Все ключи — в `engine/config.py` (неизвестный ключ — `ConfigError`), документация — в README.

### 4.2. Где лежат файлы и как копируются

- Изображения урока лежат в `media/` рядом с его `.md`, например `sources/0. Теоретическая база/3. Физика…/media/eniac.webp`. Имена файлов латиницей, короткие. Существующий аудит имён файлов проверяет и их.
- Сканер явно пропускает `dir_name` (не раздел, не страница) и запоминает соответствие «исходная папка → транслитерированная папка в `dist/`».
- Сборщик копирует `media/` каждой папки в соответствующую папку `dist/` (`dist/docs/<slug-путь>/media/…`) побайтно, в детерминированном порядке. Относительный `src="media/eniac.webp"` в странице остаётся верным.
- В `dist/` копируются только файлы с расширениями из `extensions`. `credits.toml` не копируется: он используется при сборке.

### 4.3. Синтаксис в Markdown

- Стандартный: `![Альтернативный текст](media/eniac.webp "Подпись")`.
- Встраивание в стиле Obsidian (wikilinks в книге включены): `![[eniac.webp|Подпись]]`. Файл ищется сначала в `media/` текущей страницы, затем по всей книге. Неоднозначность — предупреждение, а в `--strict` — ошибка, как у wikilinks.
- Картинка отдельным абзацем при `figures = true` превращается в:

  ```html
  <figure class="md-figure">
    <img src="media/eniac.webp" alt="…" width="1600" height="1067" loading="lazy" decoding="async">
    <figcaption>Подпись <span class="md-credit">Фото: U.S. Army · общественное достояние · <a href="…">источник</a></span></figcaption>
  </figure>
  ```

- Несколько картинок подряд в одном абзаце становятся галереей (`<div class="md-gallery">`, сетка, на телефоне — одна колонка).
- Картинка внутри текста абзаца остаётся строчной `<img>`, без `figure`.

### 4.4. Атрибуция: `credits.toml`

```toml
["eniac.webp"]
caption = "ENIAC в Школе Мура, 1946"       # подпись по умолчанию, если в тексте её нет
author = "U.S. Army Photo"
license = "PD"                              # PD, CC0, CC BY 4.0, CC BY-SA 3.0, own …
license_url = "https://creativecommons.org/publicdomain/mark/1.0/"
source = "https://commons.wikimedia.org/wiki/File:Eniac.jpg"
modified = "уменьшено до 1600 px, WebP"     # для CC BY и CC BY-SA — указывать изменения
invert_dark = false                         # схема на белом фоне: инвертировать в тёмных темах
```

- Строка атрибуции выводится в `figcaption` автоматически. Строки интерфейса («Фото», «источник», «лицензия») — в `engine/strings/ru.toml`.
- Если задан `credits_page`, генерируется страница со всеми изображениями книги: превью, подпись, автор, лицензия, источник, страницы, где изображение используется.
- Для `license = "own"` (собственная схема или рисунок) атрибуция не обязательна.

### 4.5. Размеры, отложенная загрузка, тёмные темы

- `width` и `height` — из заголовков файлов, без Pillow: PNG (IHDR), JPEG (маркеры SOFn), GIF (логический экран), WebP (VP8, VP8L, VP8X), SVG (`width`/`height` или `viewBox`), AVIF (бокс `ispe`; если разбор слишком сложен — без размеров, с предупреждением). Отдельный модуль, например `engine/media.py`, с юнит-тестами на маленьких эталонных файлах.
- `loading="lazy"` и `decoding="async"` на всех `<img>` из `media/`.
- `invert_dark = true` даёт класс, по которому стили тёмных тем инвертируют картинку (`filter: invert(1) hue-rotate(180deg)`). Это для чёрно-белых схем; на фотографиях не применять.
- Стили `figure`, `figcaption`, `.md-credit`, `.md-gallery` — в `engine/assets/style.css`, с учётом всех 15 тем. Проверить в тёмной, светлой и «винтажной» теме.

### 4.6. Увеличение по клику (лайтбокс)

- Vanilla JS в `engine/assets/main.js`, без внешних библиотек, работает по `file://`.
- Клик или Enter открывает картинку на весь экран с подписью. Esc, клик по фону или кнопка закрывают. Стрелки листают изображения страницы.
- Фокус уходит в окно и возвращается обратно, есть `aria-label`.
- По возможности переиспользовать решения полноэкранного режима Mermaid (1.13.4–1.13.6): вписывание целиком, «1:1».
- Проверка — в headless Firefox, как в `engine/tests/test_runtime.py`.

### 4.7. Аудит (`engine/audit.py`)

Работает при `enabled = true`; уровни — ошибка или предупреждение, `--strict` переводит предупреждения в ошибки, как у остальных проверок:

- отсутствующий файл — уже есть (п. 7); внешний `src` — уже есть (Offline Guard, п. 8);
- пустой `alt` при `require_alt`;
- нет записи в `credits.toml` при `require_credit`;
- лицензия не из `allowed_licenses`;
- файл больше `max_file_kb` или сторона больше `max_dimension_px`;
- неиспользуемые файлы в `media/` (предупреждение);
- суммарный объём медиа больше `budget_mb` (ошибка) и отчёт об объёме в сводке аудита.

## 7. Кратко, почему именно так

- Хотлинк из интернета нарушает Offline First и запрещён аудитом. К тому же ссылки умирают, а сайт должен работать без сети.
- Изображения в репозитории рядом с уроками удобны агенту-генератору (урок и его картинки в одном месте) и сохраняют работу по `file://`.
- Атрибуция и белый список лицензий — юридическая необходимость для публичного сайта. Автоматическая подпись избавляет от ручных ошибок.
- Лимиты размера и бюджет в аудите не дадут выйти за 1 ГБ GitHub Pages при тысячах изображений.
- Функция за ключом, по умолчанию выключена, без новых зависимостей — так требуют правила движка, и так `go-textbook` и `go-workout` не затронуты.
