Это сравнительный тест моделей. Одно и то же задание выполняют несколько моделей с разными настройками, результаты потом сравниваются. Работай так, как работал бы над настоящей задачей, но **рабочие файлы не меняй**: весь результат — в одном файле, путь к нему указан в сообщении, которым тебе передали это задание.

## Жёсткие ограничения теста

- **Читать можно всё, писать — только свой файл результата** (`Model_Eval/results/<Имя>.md`). Не редактировать, не создавать и не удалять другие файлы репозитория; не коммитить; не запускать `git add`, `git commit`, `git stash`, `git checkout`, скрипты из `scripts/`.
- Временные файлы и скрипты проверок — только вне репозитория (системный временный каталог или твой scratchpad).
- Параллельно с тобой это же задание выполняют другие модели. В `Model_Eval/results/` могут появляться чужие файлы — не читай и не трогай их.
- В конце выполни `git status --short` и убедись, что из изменений есть только твой файл результата (и, возможно, чужие файлы в `Model_Eval/results/`). Результат команды запиши в отчёт.

## Задача

Расширь и детализируй подраздел **М4.6 — KIM-1 (1976)** в `docs/03_Final/Final_Progression_v3_Claude/М04_Первые_реальные_машины.md` (сейчас строки около 357–405: 4 урока, 9 пунктов). Общая роль подраздела в модуле устраивает автора, её не перекраивай. Нужно «развернуть» его до уровня расширенных подразделов М0: больше детальных уроков, тем, примеров и подробных примечаний. Глубина нужна такая, чтобы генератор по прогрессии написал полноценные, всеобъемлющие и качественные уроки без догадок.

- **Объём:** от 10 до 14 уроков (сейчас 4).
- **Образец уровня:** `docs/03_Final/Final_Progression_v3_Claude/М00_Теоретическая_база/М0.04_Схемотехника.md` — примечание подраздела и несколько первых уроков (весь файл читать не обязательно, он большой).
- **Образец типа содержания:** модуль М4 целиком — соседние подразделы о машинах (М4.1 Apple I, М4.7 TRS-80, М4.10 шина).

## Требования к результату

- Каждый прежний пункт М4.6 сохраняется **дословно** — как название урока или пункт-секция. Ошибочный пункт исправляется, а прежняя формулировка цитируется в «Исправлено относительно прежней версии».
- Примечание подраздела — поля по разделу 3 `Prompt_Expand_Subsection.md` (Цель, Плоскость, Опора, Граница, Вперёд, Структура, Сквозная линия, Исправлено относительно прежней версии, Для генерации, Проверенные факты).
- Примечание каждого урока — поля по разделу 4 (Цель, Опора, Акценты, Граница, Вперёд, Практика, Для генерации при необходимости, Иллюстрации, Термины, Проверенные факты). «Иллюстрации» и «Термины» — в каждом уроке.
- **Факты** — каждое число, адрес, частоту, дату и атрибуцию проверяй сразу по первоисточникам или признанным справочникам (руководства MOS — KIM-1 User Manual, KIM-1 Hardware Manual, даташит MCS6530; затем признанные сайты сообщества и исходники эмуляторов; Wikipedia — последней). Существующие «Проверенные факты» М4.6 тоже перепроверь, а не переписывай на веру. Источник указывай в скобках у факта.
- **Иллюстрации** — по возможности точные имена файлов Wikimedia Commons с автором и лицензией, проверенными через API (`action=query&prop=imageinfo&iiprop=extmetadata`, поля `Artist` и `LicenseShortName`). Разрешённые лицензии — в разделе «Иллюстрации» общей части.
- Ответы к упражнениям в «Практике» проверь перед записью (при необходимости — небольшим кодом во временном каталоге).
- Кириллическая `М` в обозначениях модулей, парные `<!-- -->`, нумерация уроков с `01` без пропусков.
- Если какой-то инструмент недоступен (например, нет веб-поиска), не выдумывай: так и напиши в отчёте и пометь непроверенные факты отдельным списком. В настоящей работе это недопустимо, но в тесте честность важнее.
